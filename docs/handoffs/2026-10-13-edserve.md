## Proposed architecture

This remains a recommendation, not an approved final spec.

- Use SwiftUI for both apps, with AppKit where the Mac needs window behavior or native video rendering.
- Use iOS 27 ScreenCaptureKit in the sender's main process. Present Apple's sharing picker for full-display capture and enable the supported screen-capture background mode. No ReplayKit broadcast extension is needed for the confirmed target.
- Feed capture video samples into a native libwebrtc screen-video source. Let WebRTC encode and transport the video; do not add a redundant standalone encoding stage.
- Feed captured app-audio samples into a custom WebRTC audio-input adapter. Keep the microphone unused. Prove conversion, timing, and audio/video sync on hardware.
- Use one WebRTC engine for the direct and TURN-relayed paths. Native WebRTC is an Objective-C/C++ dependency consumed from Swift, not a web view.
- Use a small TypeScript Cloudflare Worker and a Durable Object per session for authenticated WebSocket signaling and ephemeral pairing state.
- Use STUN and Cloudflare TURN for internet connectivity. Try a direct media path when available and relay when NAT or firewalls block it. A one-to-one session does not need an SFU.
- Keep long-lived TURN keys on the backend. Issue expiring client credentials. Use QR pairing, peer approval, session expiry, and rate limits. Remember trusted devices in Keychain for repeat use.
- Video does not pass through the Worker. Media is encrypted between the WebRTC endpoints. Authenticate the peer through pairing material before making a strong security claim about a compromised signaling service.
- Later, investigate local signaling on a reachable LAN or hotspot so session setup can work without internet. Router-free Apple peer-to-peer Wi-Fi is a separate hardware experiment. Bonjour discovery does not prove WebRTC media will use AWDL.
- Investigate Mac-side USB screen capture as a separate fallback. Do not assume iOS exposes an arbitrary app-to-app USB socket or that USB works without testing.

An entirely local custom stream fails the confirmed internet requirement. A managed meeting SDK is an alternative if group calls become core, but its native Mac support needs verification. The proposed native WebRTC approach gives us control over the HDMI presentation window.
